# Resource Steward — مراقبة موارد Arena محليًا

أداة Python قياسية خفيفة في `/home/user/resource-steward`، مشغّلها `/home/user/bin/resource-steward`. **ليست إضافة أصلية لأدوات Arena، ولا اعتراضًا تلقائيًا لكل أمر**. خدمة المراقبة تعمل فقط ما دامت العملية والبيئة حيتين؛ إذا أُعيدت تهيئة sandbox يجب إعادة تشغيلها. يستعملها المساعد بوصفها فحصًا افتراضيًا قبل المهام الثقيلة، ويمكنه مراجعة قائمة رفع Google Drive.

## أوامر الاستخدام

```bash
/home/user/bin/resource-steward status     # حالة RAM ومرشحي اللقطة والإنذارات
/home/user/bin/resource-steward preflight  # 0: مسموح/تحذير، 3: توقف عن بدء عمل ثقيل
/home/user/bin/resource-steward audit      # تقدير حجم الملفات المرشحة للحفظ
/home/user/bin/resource-steward queue      # ملفات >=25 MB بانتظار مراجعة Drive
/home/user/bin/resource-steward daemon --interval 15  # خدمة مستمرة؛ ابدأها بأداة عمليات الخلفية
/home/user/bin/resource-steward run -- python3 your_analysis.py  # يحرس العملية التابعة فقط
```

**رموز الخروج:** `preflight=3` عند STOP؛ `run=124` إذا أوقف المهمة التابعة عند حد الأمان (TERM ثم KILL فقط إذا لم تخرج)؛ `daemon=4` إذا كان قفل خدمة أخرى نشطًا. القيم الأخرى من البرنامج التابع. راجع حالة المهمة ونقطة تقدمها ولا تكرر تحليلًا طويلًا دون التحقق من العملية السابقة.

## كيف يعمل

- يراقب `memory.current/max/events` و`MemAvailable`، وعدد الملفات المرشحة للّقطة وحجمها المنطقي، ومساحة القرص. تظل لقطة Arena **best-effort ~128 MB/10000 ملف**؛ الفحص تقديري ولا يثبت ما ستحفظه المنصة فعليًا.
- ينذر عند **80 MB** مرشحة للحفظ، ويرفض `run` جديدًا عند **100 MB** أو 9000 ملف؛ الإنذارات ليست حدًا رسميًا. `preflight` يرفض بدء العمل إن كان هامش الذاكرة أقل من **384 MiB** **أو تعذّر قياسه**، ويحذر دون رفض إذا قل عن **512 MiB**.
- الخدمة تطلب مراجعة أي ملف مرشح للحفظ **أو** داخل مجلد staging الخاص بها (`/home/user/.cache/resource-steward/`) حجمه **25 MB أو أكثر**، وتضع مساره/حجمه/وقت تعديله في SQLite صغيرة؛ لا ترفع ولا تحذف ولا تنقل ملفات بنفسها. أحداث التنبيه محدودة بآخر 200 سجل. لا مفاتيح Drive محفوظة محليًا.
- `run` يحرس فقط مجموعة العملية التي أنشأها ويطلب إيقافها إذا بلغ استخدام المجموعة 80% من الحد أو صار هامش الذاكرة دون 256 MiB. مراقبة أخذ العينات **لا تضمن منع OOM السريع** ولا تجعل برنامجًا غير قابل للاستئناف قابلًا للاستئناف.
- تجنب `/tmp` للملفات الكبيرة؛ هو `tmpfs` في هذه البيئة. استعمل `/home/user/.cache/resource-steward/...` مؤقتًا على `ext4` مع علمك أن `.cache` **لا يُحفظ في لقطات Arena**. البيانات المهمة الصغيرة (الكود/الحالة/الفهرس) تُحفظ خارج المجلدات المستثناة.

## سير عمل Google Drive عند وجود المساعد

1. راجع `queue` والمسار والحجم والخصوصية؛ لا تقبل اسم ملف فقط لإثبات هوية المحتوى. احسب SHA-256 محليًا بالدفعات عند الحاجة.
2. ارفع عبر موصل Google Drive المتاح للمحادثة، وليس باعتماد محلي داخل daemon. إذا تجاوز الملف حد الرفع المباشر استعمل مسارًا قابلًا للاستئناف **بعد اختباره والتحقق منه**؛ لا ترسل ملفًا ضخمًا كـbase64 إلى المحادثة.
3. احصل على **ID حقيقي** من استجابة الرفع، وتحقق من `size` وبصمة الملف البعيد إن كانت متاحة. سجل النتيجة فقط بعد هذا التحقق:

```bash
/home/user/bin/resource-steward record-upload \
  --path /home/user/path/to/file.bin \
  --drive-id 'REAL_ID_FROM_CONNECTOR' --verified-bytes 12345678
```

`record-upload` **لا يتصل بـDrive ولا يتحقق بنفسه**: يطابق فقط حجم/زمن الملف المحلي مع حالة الطابور، ويثق ببيانات Drive التي يزوده بها المشغّل. لا تحذف ملفات المستخدم الأصلية تلقائيًا؛ حذف مؤقت أنشأته الأداة ممكن بعد تحقق الرفع. إذا تغيّر الملف، يُرفض التسجيل وتحتاج إلى طلب جديد.

**110 MB = 110,000,000 بايت** حجم اختبار قبول *غير منفّذ سحابيًا بطلب المستخدم*. اختُبر فقط الاكتشاف المحلي بملف sparse افتراضي دون إنشاء 110 MB بيانات أو إرسالها إلى Drive. لا نزعم أن الرفع/الاسترجاع بهذا الحجم ثبتا بعد.

## التحليل الطويل

`run` لا يصنع checkpoints لبرنامج عشوائي؛ ينبغي تصميم التحليل نفسه في أجزاء ذات هوية ثابتة وحفظ التقدم في ملف صغير أو SQLite. لا يتضمن هذا المستودع مثالًا مستقلًا للاستئناف. شغّل الأعمال التي يجب أن تتجاوز زمن نداء bash عبر أداة العمليات الخلفية، واستعد من checkpoint إذا اختفت العملية. العملية الخلفية لا تُحفظ في اللقطة.

## اختبارات وإيقاف

```bash
python3 -m unittest discover -s /home/user/resource-steward/tests -v
# استخدم أداة إيقاف العملية للخدمة التي بدأت بأداة عمليات الخلفية
```

الخدمة نفسها لا تشغّل خادم ويب أو تستمع على منفذ. لا حاجة لـnpm أو sudo أو swap؛ التثبيت محلي تحت `/home/user`. استخدم `--help` لمعرفة الخيارات.
